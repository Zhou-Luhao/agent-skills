# 数据模型

`init` 在飞书「我的文档库」创建 Base《个人账本》，一次建好 6 张表及其字段。字段名全中文，表结构定义在 `assets/schema.json`。本文件说明每个字段的类型、写入方与口径；命令参数见 [`commands.md`](commands.md)。

## 表总览

| 表 | 主字段 | 作用 |
|---|---|---|
| 账户 | 账户名称 | 现金、微信支付宝、银行卡、理财、负债五类账户及其当前余额 |
| 持仓 | 持仓名称 | 每只股票/基金的份额、成本、最新价；市值与浮盈是公式 |
| 收支明细 | 摘要 | 所有流水：收入、支出、转账（含理财买卖、贷款本金） |
| 分类 | 分类 | 可编辑的分级分类表，脚本记账时实时解析 |
| 行情快照 | 代码-日期 | 每日收盘价/净值，按「代码_日期」唯一 |
| 资产快照 | 日期-账户 | 每个账户每天的余额/市值，净资产曲线由此聚合 |

关联方向：`持仓.理财账户 → 账户`，`收支明细.账户/转入账户 → 账户`，`收支明细.分类 → 分类`，`收支明细.持仓 → 持仓`，`资产快照.账户 → 账户`。

## ① 账户

| 字段 | 类型 | 写入方 | 说明 |
|---|---|---|---|
| 账户名称 | 文本（主字段） | `account add/edit` | 如「招行工资卡」；脚本按名称或 record_id 精确解析，重名会报歧义 |
| 类型 | 单选 | `account add/edit` | 现金 / 微信支付宝 / 银行卡 / 理财 / 负债 |
| 初始余额 | 数字（CNY，2 位） | `account add/edit` | 建账时的余额；负债填负数（剩余本金的相反数） |
| 当前余额 | 数字（CNY，2 位） | **脚本维护** | 每次 `add/edit/delete/rebuild` 后更新；理财账户 = 账户内**闲置现金**，不含持仓市值 |
| 年利率 | 数字（百分比格式） | `account add/edit` | **按小数存储**：4.2% 存 0.042；CLI 的 `--rate` 收百分数（`--rate 4.2`），脚本换算 |
| 还款方式 | 单选 | `account add/edit` | 等额本息 / 等额本金 / 随借随还；负债用 |
| 状态 | 单选 | `account add/close/edit` | 在用 / 已销户；新增默认「在用」 |
| 备注 | 文本 | `account edit` | |

当前余额不是公式：转账/还款会同时影响两个账户，表内公式无法跨行聚合，所以由脚本在每次联动写入时更新。不要手工改当前余额来“调账”——期初错了改初始余额，流水错了改明细，然后 `rebuild`。

## ② 持仓

| 字段 | 类型 | 写入方 | 说明 |
|---|---|---|---|
| 持仓名称 | 文本（主字段） | `holding add/edit` | 如「贵州茅台」「易方达中小盘」 |
| 代码 | 文本 | `holding add/edit` | 股票 `sh600519` / `sz000001`；基金 6 位数字 `110011` |
| 品种 | 单选 | `holding add/edit` | 股票 / 基金；决定行情数据源与赎回盈亏分类 |
| 理财账户 | 关联 → 账户 | `holding add/edit` | 持仓归属的理财账户；买卖时账户必须与之一致 |
| 当前份额 | 数字 | **脚本维护** | 买入加、卖出减，保留 4 位；份额归零置「已清仓」 |
| 成本价 | 数字（4 位） | **脚本维护** | 买入按加权均价更新；卖出不改成本价 |
| 最新价 | 数字（4 位） | 行情流程 | 最近一次「已落」的收盘价/净值；首次回补前为空 |
| 最新价日期 | 日期 | 行情流程 | 与最新价同源，不会回退到更旧日期 |
| 市值 | 公式 | 飞书自动 | `[当前份额]*[最新价]`；脚本永不写入 |
| 浮动盈亏 | 公式 | 飞书自动 | `([最新价]-[成本价])*[当前份额]`；脚本永不写入 |
| 状态 | 单选 | **脚本派生** | 持有 / 已清仓；由当前份额是否为 0 派生 |
| 期初份额 | 数字 | `holding add/edit` | `rebuild` 的重放起点；`holding add` 默认等于当前份额 |
| 期初成本 | 数字（4 位） | `holding add/edit` | `rebuild` 的重放起点；默认等于当前成本价 |

市值/浮盈是**公式字段**，脚本只读不写。最新价未知（尚未回补行情）时，查询与报告按 0 展示市值/浮盈，不虚构亏损。

## ③ 收支明细

| 字段 | 类型 | 说明 |
|---|---|---|
| 摘要 | 文本（主字段） | 如「午饭」「11月房贷」 |
| 日期 | 日期 | `YYYY-MM-DD`；脚本写入 `YYYY-MM-DD 00:00`，统计用闭区间 |
| 类型 | 单选 | 收入 / 支出 / 转账 |
| 金额 | 数字（2 位） | 用户录入的收支/转账金额恒正；赎回自动生成的已实现盈亏收入行**可为负**（亏损） |
| 账户 | 关联 → 账户 | 收支的发生账户；转账为转出账户；理财买卖为理财账户 |
| 转入账户 | 关联 → 账户 | 仅转账；理财买卖的份额行账户与转入账户相同（自转） |
| 分类 | 关联 → 分类 | 收入/支出必填；转账不填 |
| 持仓 | 关联 → 持仓 | 仅理财买卖的份额行 |
| 成交价 | 数字（4 位） | 仅理财买卖 |
| 份额 | 数字（4 位） | 仅理财买卖 |
| 备注 | 文本 | 贷款拆分明细、多明细组 tag `#Gxxxxxxxx` 等 |
| 创建时间 | 创建时间（自动） | `rebuild` 在同一日期内按它和 record_id 稳定排序 |

### 多明细组

一笔操作可能写成多行，共用同一备注尾部的组 tag（形如 `#G1a2b3c4d`）：

- 理财申购：2 行（银行卡→理财的转账 + 理财现金↔持仓的份额行）；
- 理财赎回：3 行（理财→银行卡的转账 + 已实现盈亏收入 + 份额行）；
- 贷款还款：2 行（利息支出 + 本金转账）。

`edit` 改备注时会保留 tag；`delete` 会按 tag 自动整组删除；`rebuild` 以组为单位重放，避免把理财买卖的转账行按行求和而重复计现金。**不要手工删掉备注里的 `#G` tag，也不要只删组里的一行**。

## ④ 分类

| 字段 | 类型 | 说明 |
|---|---|---|
| 分类 | 文本（主字段） | 全名，格式 `类型·一级·二级`；没有二级时是 `类型·一级`，如 `支出·其他`、`收入·报销` |
| 类型 | 单选 | 收入 / 支出；`--kind auto` 据此判方向 |
| 一级 | 文本 | 如「餐饮」 |
| 二级 | 文本 | 如「午餐」；可为空 |

分类表由用户随时增删，脚本**每次记账都重新查表解析**，不缓存死列表，也**不会自动创建**分类。完整预置清单见 [`categories.md`](categories.md)。

## ⑤ 行情快照

| 字段 | 类型 | 说明 |
|---|---|---|
| 代码-日期 | 文本（主字段） | 业务唯一键 `<代码>_<YYYY-MM-DD>`，如 `sh600519_2026-11-17` |
| 代码 | 文本 | `sh600519` / `110011` |
| 日期 | 日期 | 行情对应交易日 |
| 收盘价/净值 | 数字（4 位） | **可空**：`待回补` 行先占位，回补到值后填 |
| 状态 | 单选 | 已落 / 待回补 / 无数据 |
| 更新时间 | 修改时间（自动） | 飞书自动维护 |

状态含义：`已落` = 已有价格；`待回补` = 该日期尚无价格（如基金净值延迟），后续触发时重试；`无数据` = 超过 7 天仍无价格（多为非交易日/QDII 延迟），不再无限回补。

## ⑥ 资产快照

| 字段 | 类型 | 说明 |
|---|---|---|
| 日期-账户 | 文本（主字段） | 业务唯一键 `<YYYY-MM-DD>_<账户名称>` |
| 日期 | 日期 | 快照日期 |
| 账户 | 关联 → 账户 | |
| 余额/市值 | 数字（CNY，2 位） | 负债为负；**理财账户 = 该账户闲置现金 + 其名下持仓市值合计**；其他账户 = 当前余额 |
| 备注 | 文本 | 新建行留空；已存在的行不覆盖用户手写备注 |

同一「日期_账户」重复执行只更新、不重复建行。快照只给「在用」账户落行，销户账户不污染历史曲线。

## 净值口径

- **理财账户的当前余额 = 账户内闲置现金**，不是总资产；持仓市值单独在《持仓》表里。
- **申购是两步**：银行卡 → 理财账户的现金转账（银行卡 −金额），加一笔理财现金 → 持仓份额的份额行。理财账户闲置现金净变化为 0，钱变成了持仓。
- **赎回对称**：份额 → 理财现金，再把现金转到银行卡；理财账户闲置现金净变化为 0，银行卡 +到账金额。
- **已实现盈亏只是收入统计**：赎回时自动生成的盈亏行（可正可负）进入收入分类，但它**不改变**理财账户现金，重放/快照都不把它当现金收入重复计入。
- **净资产 = Σ 在用账户当前余额 + Σ 在用理财账户名下持仓市值**。负债余额本身为负，直接相加即自然抵减；销户账户与已清仓持仓不计。
- **资产快照不重复计市值**：理财账户那一行已经把「闲置现金 + 名下持仓市值」合成一个数；把所有账户行按日期求和就是净资产，不要再额外加一遍持仓市值。
- 周报/月报的曲线来自资产快照按日期聚合；报告生成时会强制落一份当天快照，且**报告期间包含今天时**，把当天实时净值作为曲线末点（同一天只保留一个点）。`add` 每周首次触发补落的是**上周日**快照，余额取执行时的当前值近似；需要精确历史点时用 `snapshot --date` 显式补。

## 状态与期初字段

| 字段 | 可选值 | 行为 |
|---|---|---|
| 账户.状态 | 在用 / 已销户 | 销户只改状态，不删账户；`query balances` 的合计、`snapshot`、报告实时净值只统计在用账户 |
| 持仓.状态 | 持有 / 已清仓 | 买入恢复「持有」，卖光置「已清仓」；查询/报告的持仓视图只含持有，行情只更新持有持仓（已清仓的待回补行仍会回补） |
| 账户.初始余额 | 数字 | `rebuild` 的账户重放起点；`account edit --opening` 只改它，改完应 `rebuild` |
| 持仓.期初份额 / 期初成本 | 数字 | `rebuild` 的持仓重放起点；`holding edit --opening-shares/--opening-cost` 只改基线，`--shares/--cost` 只改当前值 |
| 行情快照.状态 | 已落 / 待回补 / 无数据 | 见上；回补与过期规则见 [`quotes.md`](quotes.md) |

`rebuild` 只信任「初始余额 + 期初份额/期初成本 + 全部明细」，**不信任当前余额、当前份额、状态**；因此手机端改过金额/账户/日期或删行后，跑一次 `rebuild` 即可恢复一致。
