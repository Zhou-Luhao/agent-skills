# 报告说明与交付契约

本文件说明 `oura` 技能生成的四类产物：日报、周报、月报及其 Markdown 摘要。**所有数字由 `scripts/aggregate.py` 计算**，agent 只负责解读，不改数字。

## 产物清单

| 命令 | 产物 | 文件名 |
|---|---|---|
| `daily --date D` | HTML + MD | `oura-<D>-daily.html` / `.md` |
| `weekly --date D` | HTML + MD | `oura-<周一日期>-weekly.html` / `.md` |
| `monthly --date D` | HTML + MD | `oura-<当月1日>-monthly.html` / `.md` |

- 周报锚点用**所在周的周一**（ISO 周，周一至周日），不是 `--date` 当天
- 默认输出到系统「下载」目录；`--out DIR` 或 `OURA_REPORT_DIR` 可覆盖
- 命令成功时向 stdout 打印两份产物的**绝对路径**，把路径原样告诉用户

## HTML 结构

单文件，内联 CSS，**无 `<script>`、无任何外链**（`src`/`href` 只允许锚点），离线可打开。

- **日报**：头部（日期 + 账号上下文 + 三分数卡）→ 睡眠（分期时间轴 + 指标表 + 小睡）→ 扩展指标（SpO2 / 压力 / 恢复力 / 心血管年龄 / VO2max / 就寝建议 / 休息模式 + 三组贡献因子）→ 事件（锻炼 / 会话 / 标签）→ 心率曲线 → 设备
- **周/月报**：三分数趋势线 → 每日睡眠时长柱状 → 汇总表（均值 / 最低 / 最高 / 标准差 / 天数）→ 最佳最差日 → 环比 → 缺失日期

## 指标口径（不要自行换算或再归属）

| 口径 | 规则 |
|---|---|
| 睡眠时长 | 聚合层以**秒**存储，仅渲染层换算为「X 小时 Y 分」 |
| 睡眠归属日 | 直接采用 API 返回的 `day`（= 睡眠结束当天的本地日期），**不做二次归属** |
| 主睡眠 vs 小睡 | 主睡眠 = `long_sleep`；小睡 = `sleep` + `late_nap`，**只展示不并入主睡眠时长**（Oura 已把它计入当日分数，合并会双重计数） |
| 已删除/误检 | `deleted`、`rest` 一律排除，不进入任何统计 |
| 时区 | 「今天」「最近 N 天」与时序数据的日切分一律用**系统本地时区** |
| 标准差 | **总体标准差**（周期内全体日即统计总体） |
| 缺失数据 | 缺失的日期会在报告中显式列出，不静默跳过；整域缺失显示「无数据」 |

## 部分周期

周中出周报、月中出月报是常态。此时：

- 报告标记 `is_partial` 与已过天数，HTML 顶部显示徽章
- 环比**按已过天数对齐上期同天数**（如本周已过 3 天，就与上周前 3 天比），
  并在环比区块写明「本期截至 D（N 天），与上期同天数对比」
- 不要用「本周 3 天的总量」去比「上周 7 天的总量」——那必然显得大幅下降

## Markdown 摘要

与 HTML 同口径的核心数字表 + 末尾固定的解读区：

```markdown
## 解读

<!-- AGENT-APPEND-BELOW -->
```

**agent 的约定**：

1. 只在 `<!-- AGENT-APPEND-BELOW -->` **之后**追加内容；
2. **不得修改**表格里的任何数字，也不得新增、删除或重排表格行；
3. 解读基于表格中的数字做因果/趋势说明，不要引入表中没有的数值；
4. 解读控制在 3–6 句，先说最值得注意的变化。

## 交付契约（含飞书钩子）

按以下顺序决定产物去向：

1. **默认**：产物留在输出目录，把两个绝对路径告诉用户即可，不要主动推送。
2. **用户明确要求推送，且当前环境装有 `lark-*` 技能**：
   - HTML 文件 → 用 `lark-im` 上传并发送到用户指定会话（HTML 可直接当附件预览）
   - MD 摘要 → 用 `lark-doc` 创建云文档（表格在云文档里可正常渲染）
   - 推送前先把本地路径告诉用户，推送失败时至少本地产物可用
3. **用户要求推送但没有 `lark-*` 技能**：说明当前环境缺少飞书能力，只提供本地路径；
   **不要**尝试用其他方式（邮件、第三方 API、自建脚本）偷偷送达。

> 飞书**互动卡片不支持 Markdown 表格**。要发表格就用 `lark-doc` 云文档；
> 若要发卡片消息，改用「核心指标」的列表版（每行「指标：数值」）。

## 报告里没有的东西

- 不做诊断或医疗建议：只描述数据变化，不推断病因
- 不预测未来分数
- 不比较他人数据（只有用户本人的数据）
